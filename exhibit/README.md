# R1 车队运维调度 · 展示台

一个页面三个画面，默认进入 **展会主屏**；按 **1 / 2 / 3** 切换（或点顶部标签）：

1. **车队调度**：2 台 R1 Pro + 2 台 R1 Lite 全部参与同一辆 C17 的运输。满车按 **Pro 01 → Lite 01 → Lite 02 → Pro 02** 依次交接，工位确认卸空后反向接力补回源区。
   本地离散事件模拟，不连接真机。有三处落地交接位、调度决策（候选与已选）、八步任务进度、每台完成数、执行记录与故障注入。每轮 22 项成功动作、6 次交接，均先放车、原机退出，下一台再接取。
2. **模型推理回放**：`replay_panel/` 生成的真机 run 回放（三路相机、动作预测、下发目标与执行反馈、时延、事件时间轴），放在 `static/replays/` 里即可被列出。
3. **展会主屏**：放大头部与双腕的真实记录帧，旁边展示同次运行的任务、动作模型身份、32 步预测、已下发步数及反馈。底部四个关键时刻可一键定位；“查看此刻的动作细节”进入同一条记录、同一时间的详细回放。现有两条记录是取布放筐任务，**不是医院运输录像，也不是 VLM 文字推理**。相机为原始 224×224 采样帧。

主屏提供“真机记录 / 实时观察”来源选择。默认地址使用真实日志回放；通过 `start_live.sh` 启动可自动接收相机快照并进入实时观察。只读快照合同及接入说明见 [LIVE.md](LIVE.md)。三种画面明确区分真实记录、四机模拟和实时源。

原两机模拟内核保持不变，四机流程由新增的 `FourRobotEngine` 扩展，复用原有派发、资源预约、回执校验和故障恢复机制。内部 ID `R1 / R2` 显示为 Pro 01 / Pro 02，新增 `R3 / R4` 显示为 Lite 01 / Lite 02。四台都来自后端状态并有真实的模拟任务；所有位置、运输与交接能力均为本地模拟。

## 启动（Windows / Linux / Mac，Python 3.9+，无第三方依赖）

Linux 相机实时观察可直接运行项目根目录的 `./start_live.sh`，自动接收 `172.18.21.239:8772/snapshot` 并打开实时模式。换机器人用 `--robot-ip`；完整说明见项目根目录 `LIVE_START.txt`。

项目只保留根目录 `start_live.sh` 一个启动文件。执行 `./start_live.sh` 自动接收真实相机并打开实时观察；机器人端必须已有新鲜画面。保持终端开启，Ctrl+C 停止本次启动的进程。端口冲突可用 `./start_live.sh --port 8773`。程序不会结束不属于本次启动的服务。

以下是开发或高级手动调用，绕过相机接收器（从 exhibit 目录运行）：

```bash
python3 server.py --port 8771
```

Windows 上用 `py server.py --port 8771`。本机浏览器打开 <http://127.0.0.1:8771/>，按 F11 全屏。服务监听 `0.0.0.0`，支持本机和局域网访问。

局域网同事使用 `http://服务电脑的局域网IPv4:8771/`，例如本机 Wi-Fi 地址为 `172.18.20.213` 时访问 `http://172.18.20.213:8771/`；换端口时同步替换 URL 中的端口。不要在同事电脑上使用 `127.0.0.1`，也不要使用 `0.0.0.0` 或代理软件的虚拟网卡地址。IP 变化后使用新地址；Windows 可用 `ipconfig`、Linux 可用 `ip -br address` 查看。

服务只接受 localhost 或连接实际到达的本机 IPv4 的 Host，并保留同源请求校验。若本机通过局域网 IP 能访问而同事仍无法连接，继续检查两台电脑的网络互通、Wi-Fi 客户端隔离和防火墙入站端口规则。修改服务代码后，先在原启动终端按 Ctrl+C，再重新运行启动脚本。

- 默认地址打开展会主屏；`#fleet` 直接打开四机调度，`#replay` 直接打开详细回放。
- 默认四机，数据库在 `data/fleet-four.sqlite3`，重启保留状态；想从头来点"重置"。
- 原两机内核可通过 `--fleet-size 2` 单独运行，默认库为 `data/fleet.sqlite3`，用于旧流程回归；展台画面按四机设计。四机拒绝打开两机旧库，避免改写旧状态。
- 测试：`python3 -m unittest discover -s tests -v`
- 从项目根目录测试：`python3 -m unittest discover -s exhibit/tests`。

## 展台无人时

- **自动演示**（底栏，默认开）：页面打开就开始运行；任务完成停 8 s 后自动换下一个场景（标准交接 → 满车位被占 → 首次抓取失败）重跑。按"暂停"或"单步"会自动关掉它。
- 掉线或待核对时停止自动推进，点“恢复并核对”后继续。启动、重置或调度出错时显示提示并停止自动重试，可检查后手动开始或重置；取消“自动演示”会阻止正在换场景的后续启动。
- **自动轮播**（顶栏，默认关）：勾上后每 45 s / 90 s / 3 min 按“展会主屏 → 车队调度 → 模型推理回放”循环。
- 主屏从第一组相机输入开始回放，结束停留 3 s 后循环；离开暂停，返回继续。轮播进入详细回放从 0 开始播放，离开暂停；从主屏“查看此刻的动作细节”进入时，定位到同一时刻并暂停，方便讲解。

## 讲解时

- 建议先用主屏展示“相机输入 → 模型动作 → 实际下发与反馈”，再点“查看此刻的动作细节”，最后切到四机调度讲接力与异常恢复。底部四个章节只跳转已有日志中的时间点，不生成额外推理或事件。
- 底栏"制造变化"六个按钮：占用主交接位 → 调度改走交接 A 备用位；下次抓取失败 → 失败回执与重试；迟到回执 → 旧回执不会完成当前任务；机器人掉线 → 任务进入待核对，"恢复并核对"后继续。
- 决策可切到"模型调度"（需按 `MODEL.md` 配置模型服务，否则保持规则调度）。
- 主屏与回放：空格暂停、← → 跳 2 s、点时间轴跳转、顶部“运行记录”换另一条 run。详细回放支持悬停看数值；按 1/2/3 可从 iframe 内切换画面，在输入或下拉控件中操作时不抢快捷键。
- “目标/反馈偏差”是当前段已下发记录中，双臂 14 个关节目标与同条反馈的平均绝对偏差（MAE，rad）；不混入夹爪、底盘、躯干。同条反馈在指令下发前采集，未经时序对齐，因此不是跟踪精度。时间轴红框▼标记 RTT > 本条 run 中位数 × 1.5，悬停可看具体阈值。
- “闭合条件”是右爪反馈达到检测阈值，“张开指令”是后续张开目标触发日志；二者都不直接证明抓稳或物体已入筐。现有记录的任务结果保持“待核验”。

## 文件

| 路径 | 内容 |
|---|---|
| `server.py` | 本地 API + 静态文件；提供 `/api/replays`、`/api/evidence`、`/api/telemetry` 和 `/replays/*.html`（仅回放页放宽 CSP，允许内联脚本） |

| `planner.py` | 规则 / 模型候选选择；仅四机模式调整提示中的数量，原两机提示与行为不变 |
| `static/index.html` / `app.js` / `style.css` | 展示台前端（新写） |
| `static/showcase.js` / `showcase.css` | 展会主屏、真实记录播放与实时入口；无外部资源 |
| `static/replays/` | 回放 HTML |
| 根目录 `start_live.sh` / `live_launcher.py` | 唯一启动入口及内部接收监督模块；`launcher.py` 为服务与浏览器内部辅助模块 |
| `instance_identity.py` | 根据目录、数据库和实时配置生成本地实例散列，防止复用另一份展示服务 |
| `preview_showcase_1920x1080.png` / `preview_fleet_1920x1080.png` / `preview_replay_1920x1080.png` | 无头 Chrome 截的三个画面预览 |
| `qa/browser_report.json` / `qa/browser_check.mjs` | 22 项浏览器检查记录及开发用复查脚本；复查脚本需 Node 20+，展台运行不需要 Node |
| `qa/showcase_report.json` / `qa/showcase_check.mjs` | 26 项主屏浏览器检查：同源记录、切换竞态、同时间详情、实时失效清空、键盘与布局 |

开发复查：`node --experimental-websocket exhibit/qa/browser_check.mjs`（项目根目录）；默认使用 Mac Chrome，可用 `CHROME` 指定浏览器路径。它创建临时本地模拟服务和浏览器，不触碰已有数据库或机器人。检查覆盖四台实际状态与八步进度、完整往返 22 项动作、四机自动换场景、位移插值、接车连续性、事件高亮、故障不重试、取消自动演示竞态、iframe 快捷键、轮播重播和布局。Windows Chrome/Edge 的实际键盘与双击启动仍需展台电脑确认。

回放数值复查也包含在 browser_check.mjs：对两条原始记录独立计算双臂偏差，逐段检查 RTT 异常悬停文案；当前共 22 项车队与回放浏览器检查。

主屏复查：`node --experimental-websocket exhibit/qa/showcase_check.mjs`；使用临时数据库、浏览器及明确标为 QA 的合成快照验证失效行为，合成数据不进入展台回放。Python 完整回归共 69 项。
