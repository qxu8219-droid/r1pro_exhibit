【1. 准备与启动】
完整展示需要：Python 3.9+，本地 Chrome 或 Edge，可写的本地文件夹。
推荐屏幕：1920×1080，浏览器缩放 100%。无需 pip；实时画面需要与机器人局域网互通。
交付包不附带 Python / 浏览器，正式开展前在目标电脑安装并演练一次。

当前 Linux 三个入口：
- 完整执行：./start_robot_and_live.sh，包含真实运动；先阅读FULL_START.txt并准备现场。
- 离线备用：./start_offline.sh，无需机器人或网络，默认8771，显示原真实记录与四机模拟。
- 实时观察：./start_live.sh，默认8773，连接机器人数据。
以下为实时启动说明；离线完整步骤见 OFFLINE_START.txt。
运行即可；live_settings.json 已保存连接、端口和数据位置，每次启动自动只读测量时差。
在包根打开终端运行 ./start_live.sh，或选择“在终端运行”。
默认连接192.168.5.6；检查相机桥及VLA采集器，缺少时通过独立新目录中的启动器恢复，按提示输入SSH密码，然后打开实时观察。
启动终端保持开启，浏览器会自动打开展示。
本机地址：http://127.0.0.1:8773/
局域网同事访问：http://服务电脑的局域网IPv4:8773/
例如服务电脑地址为 172.18.20.213，则访问 http://172.18.20.213:8773/。
同事不要使用 127.0.0.1；服务电脑 IP 变化后，改用新地址。
完整展示不要直接双击 exhibit/static/index.html。
包内不含运行数据库；首次启动自动建立干净的四机模拟。

【2. 三个画面与快捷键】
3 = 展会主屏（默认）：三路相机、模型动作、下发与反馈记录。
2 = 模型推理回放：32 步预测、目标和反馈曲线、时延与事件。
1 = 车队调度：2 台 R1 Pro + 2 台 R1 Lite 接力同一辆 C17。
也可点顶部标签切画面。

主屏 / 详细回放：空格暂停或播放，左右箭头跳 2 秒，时间轴定位。
主屏四个章节可一键定位；“查看这一刻的模型细节 ↗”进入同一记录、
同一时间并暂停。下拉框或输入框有焦点时不抢快捷键，先点空白处。

【3. 十分钟熟悉】
0–1 分钟：启动；关掉顶部“自动轮播”；主屏保持“真实运行记录”。
1–3 分钟：试暂停、播放、从头播放、四个章节；换一次运行记录再切回第一条。
3–4 分钟：点“03 闭合条件”→“查看这一刻的模型细节 ↗”，核对同时间。
4–5 分钟：试 1 / 2 / 3 切页、空格和左右箭头。
5–7 分钟：车队页关“自动演示”，选“规则调度”“标准交接”，重置、开始运行。
7–8 分钟：有机器人正在执行时点“机器人掉线”；看待核对，再点“恢复并核对”。
8–9 分钟：按下一节讲解；不必等完整往返结束。
9–10 分钟：练退出、重启与无人展示设置，检查现场屏幕。

【4. 三分钟讲解脚本】
准备：关“自动轮播”和车队“自动演示”，决策保持“规则调度”。
主屏选第一条真实运行记录。所有故障按钮仅改变本地模拟。

0:00–0:35 / 按 3，播放主屏，指相机、预测、反馈。
“这是 R1 Pro 取布放筐的真实运行记录。相机、模型预测和反馈来自同一次运行，
我们能把一个动作的依据和过程放在一起看。”

0:35–1:10 / 点“03 闭合条件”，再点“查看这一刻的模型细节 ↗”。
“现在停在同一时刻。虚线是本段 32 步动作预测，另外的曲线展示目标与反馈。
夹爪条件有日志，是否抓稳、是否入筐还要独立核验。”

1:10–1:55 / 按 1，标准交接→重置→开始运行，指向 C17、交接位与记录。
“四机模拟说明运输组织：Pro 01 → Lite 01 → Lite 02 → Pro 02。
交接先放车、退出，再由下一台接走；工位模拟确认卸空后，空车反向补回。”

1:55–2:30 / 有机器人正在执行时点“机器人掉线”，再点“恢复并核对”。
若仍暂停，点“开始运行”。
“通信中断后先保留资源并等待核对。这里由模拟器核对保存状态再重试；
真机接入需要真实设备回执与状态核验。”

2:30–3:00 / 确认恢复信息，按 3，点“从头播放”。
“一部分是真实动作的可追溯记录，一部分是接力运输和恢复的调度模拟。
下一步把医院现场观察与执行回执接到同一条证据链上。”

【5. 无人展示】
先到车队页选“规则调度”“标准交接”，点“重置”，勾“自动演示”。
再勾顶部“自动轮播”，建议选“每 90 秒切换”。未开启时选项置灰；开启或改间隔后重新计时。

自动轮播（顶部，默认关）：主屏→车队→详细回放定时换页。
进入详细回放会从头播；主屏离开暂停、返回继续。
自动演示（车队底栏，默认开）：车队完成一轮后停 8 秒，自动切换
标准交接→满车位被占→首次抓取失败。它不负责切页。
掉线 / 待核对会等待处理；点“恢复并核对”，必要时“开始运行”。
点车队“暂停”或“单步”会关闭自动演示；切页本身不会暂停车队模拟。
正式离开前先在目标电脑演练一轮。

【6. 退出与重启】
Windows / Linux：Alt+F4 关闭展示窗口。Mac：⌘W。
再到启动终端按 Ctrl+C 停止本次服务。只关浏览器不会停止服务。
若显示“复用现有展示服务”，去最初启动它的终端停止。
重启用同一启动脚本。模拟进度保存在本地数据库；想从头讲就点车队“重置”。

【7. 现场故障处理】
先检查：Windows 双击 check.bat；Linux / Mac 在包根运行 sh check.sh。
只检查 Python 与 SHA256 文件完整性，不启动展示或修改模拟进度。

没有 Python：完整展示需安装 Python 3.9+；Windows 安装时加入 PATH。
可用 py -3 --version / python --version（Windows）或 python3 --version 查版本。
无法及时安装时，使用下方“仅回放备用路径”。

端口占用 / 旧版本：在包根终端换端口，不必结束不认识的程序：
  ./start_live.sh --port 8772
  地址改为：http://127.0.0.1:8772/
启动器只复用同目录、数据库与实时配置匹配的服务，不会误用另一份交付包。

白屏 / 无法连接：确认启动终端还在，完整解压，地址为服务电脑的 http 地址，
不是直接打开 index.html。主屏选“真实运行记录”，稍等后刷新；
仍异常就关浏览器、终端 Ctrl+C、重新启动。先用独立回放顶上。

UNKNOWN / 待核对：车队“恢复并核对”，必要时“开始运行”。
只想重新开始：规则调度→标准交接→重置→开始运行。
重置清掉本轮模拟进度，不会改真实回放记录。

模型未配置：切回“规则调度”，重置并开始；标准交付无需模型配置。
技术同学要实验模型接口时看 exhibit/MODEL.md，配置后需重启并提前验证。
当前模型调度输入是模拟状态和候选动作 JSON，不含相机。

实时观察未连接：检查机器人网络与相机桥；VLA信息未接入时另检查只读VLA旁路，画面与VLA连接独立。
接入约定在 exhibit/LIVE.md；真实相机快照链路已接通。

【8. 仅回放备用路径】
无需 Python，无需启动服务。用本地 Chrome / Edge 双击：
exhibit/static/replays/replay_live_run_20261019T093806212123Z.html
打开即自动播放，到尾循环。此路径只有详细回放，没有主屏和车队模拟。
Windows / Linux 普通窗口 F11 全屏；Mac 可用浏览器全屏菜单。

【9. 对外讲解口径】
• 相机画面是真机取布放筐运行记录，224×224 采样帧，不是医院直播。
• 四机运输是本地模拟，当前没有连接四台实机。
• 这两条记录有动作模型输出，无 VLM 文字决策；默认车队采用规则调度。
• 结果保持“待核验”；闭合条件 / 张开指令不是独立任务成功判定。
• 目标/反馈偏差未做时序对齐，不代表跟踪精度；两条记录不能给出整体成功率。
• 相机实时链路已验证；VLA采集器只在独立新目录内运行，原机器人文件不变。
